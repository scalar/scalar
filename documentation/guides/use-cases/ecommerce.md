Commerce APIs serve many callers at once: your storefronts, merchant and app partners, and AI agents that shop for people. Scalar turns one OpenAPI document into the docs, SDKs and MCP server each of them needs, and keeps them in step as the API changes. [PAR Technology](/customers/partech), which builds software for restaurant and retail brands, publishes its ordering, loyalty and POS APIs for partners with Scalar.

## How it works

<scalar-steps>
<scalar-step title="Publish your OpenAPI document">

Push it to the [Registry](/products/registry) with `scalar registry publish`, or from [GitHub Actions](/products/registry/github-actions) on every merge.

</scalar-step>
<scalar-step title="Choose what to generate">

A docs site for partners, SDKs in the languages your storefront and partner teams write, and an MCP server with the operations agents may use.

</scalar-step>
<scalar-step title="Change the API once">

Point your SDKs at a semver range such as `^1.2.0`, and each matching new version rebuilds every language and opens pull requests. The docs republish on merge, and the MCP tools map straight to the document's operations.

</scalar-step>
</scalar-steps>

## Ready for shopping agents

- **Shoppers sign in as themselves.** With [OAuth passthrough](/products/agent/authentication/oauth-passthrough), they sign in through your own authorization server, and Scalar forwards the token to your API without storing it.
- **A large API stays small in context.** The [MCP server](/products/agent/mcp) exposes a fixed set of tools and fetches an operation's details only when the agent needs them.
- **Context for coding agents.** Every generated SDK ships an Agent Skill and an `api.md` listing each method. See the [SDK generator](/products/sdk-generator).

## Questions

<scalar-detail title="Can an agent place orders we have not allowed?">

No. Each operation you expose is set to Search, which only lets the agent look it up, or Execute, which sends a real, authenticated request. Keep checkout on Search until you are ready.

</scalar-detail>

<scalar-detail title="Which languages can our SDKs cover?">

TypeScript, Python, Go, Java, Kotlin, Ruby and a CLI are generally available, and six more languages are experimental. One language for one API counts as one SDK, and every plan includes one. See [pricing](/pricing) for more.

</scalar-detail>

<scalar-detail title="Do we have to run the MCP server ourselves?">

No. Scalar hosts it at `mcp.scalar.com`, or on a subdomain of yours with one CNAME record. Hosted MCP servers are on the Pro, Business and Enterprise plans.

</scalar-detail>
