## How it works

<scalar-steps>
<scalar-step title="Describe the API once">

Put your security schemes and webhooks, such as a settled payment, in one OpenAPI document in the [Registry](/products/registry).

</scalar-step>
<scalar-step title="Generate docs, SDKs and an MCP server">

SDKs wire authentication from your security schemes, and [webhook helpers](/products/sdk-generator/webhooks) check each delivery's signature before decoding the event.

</scalar-step>
<scalar-step title="Ship changes through review">

When the document changes, Scalar rebuilds each SDK and opens a pull request in your own repository, and the new code samples appear in your API reference.

</scalar-step>
</scalar-steps>

## Access and security

- **SOC 2 Type 1.** Scalar has a SOC 2 Type 1 report and GDPR privacy practices. [Security](/security)
- **SSO for your team.** SAML SSO through Okta, Microsoft Entra ID, Google and others, on the Business and Enterprise plans. [SSO guide](/resources/sso/getting-started)
- **Partners without seats.** Access groups admit partners to private docs and MCP servers by email domain or address, without a seat on your team, from the Pro plan up. [Private docs](/products/docs/configuration/private-docs)
- **Keys stay on the server.** Agents never receive the upstream credentials an MCP server stores, and each access group can use its own API key. [MCP authentication](/products/agent/authentication)

## Questions

<scalar-detail title="Are SDK retries safe for payment requests?">
Generated SDKs retry network errors and 408, 409, 429 and 5xx responses, two attempts by default, and honor `Retry-After`. Name the idempotency header your API expects, and every request except a `GET` carries a key that is resent unchanged on each retry, so your API can recognize a repeat. See [SDK configuration](/products/sdk-generator/configuration/overview).
</scalar-detail>

<scalar-detail title="Can we publish SDKs to our internal package registry?">
Yes. Alongside the public registry, a workflow you add to the SDK repository can publish to JFrog Artifactory, AWS CodeArtifact, Sonatype Nexus or another host, and builds never overwrite it. See [private registries](/products/sdk-generator/publishing/private-registries).
</scalar-detail>

<scalar-detail title="Can an agent move money through the MCP server?">
Only through operations you set to execute. Search lets an agent look up an operation without sending a request, and execute sends a real, authenticated one, so leave payouts and transfers out or in search mode. See [MCP servers](/products/agent/mcp).
</scalar-detail>
