## How it works

<scalar-steps>
  <scalar-step title="Publish the OpenAPI document">

Push it to [Registry](/products/registry) from CI with `scalar registry publish`, and lint every change against shared Spectral rules.

  </scalar-step>
  <scalar-step title="Connect the docs and SDKs">

Connect the docs to your repository with [Git Sync](/products/docs/integrations/github), and point each SDK at the document by exact version or a semver range such as `^1.2.0`.

  </scalar-step>
  <scalar-step title="Review, then ship">

Docs pull requests get [preview deployments](/products/docs/deployment/preview-deployments), and SDK changes arrive as release pull requests. Merge, and the docs publish while your own workflows release the packages.

  </scalar-step>
</scalar-steps>

## Developer experience

- [Code samples from the generated SDKs](/products/sdk-generator) appear in your API reference, and examples you wrote by hand are kept.
- [Your edits to generated code](/products/sdk-generator/custom-code) survive every rebuild through a three-way merge.
- [Versions](/products/docs/configuration/versions) keep older API releases readable beside the current one, behind a version selector.
- [Clerk and Tailscale](/customers) publish their API docs with Scalar Docs.

## Questions

<scalar-detail title="Can the docs live in our repository?">

Yes. Content is Markdown and MDX with one `scalar.config.json`, and [Git Sync](/products/docs/integrations/github) publishes when you merge. The Scalar GitHub App only reaches the repositories you select, and Git Sync is on Pro and above.

</scalar-detail>
<scalar-detail title="Which SDK languages are ready for production?">

TypeScript, Python, Go, Java, Kotlin, Ruby and the CLI are generally available and carry end-to-end tests. C#, PHP, Rust, Swift, Dart and C++ are experimental, so talk to us before you depend on one.

</scalar-detail>
<scalar-detail title="Who owns the SDK packages?">

You do. Each SDK lives in your repository under your package name and publishes to your registry accounts. Scalar opens pull requests against it and never cuts tags or releases for you.

</scalar-detail>
